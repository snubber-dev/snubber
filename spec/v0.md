# snubber-record — v0

`format.json` is the authority; this file is prose about it and restates nothing mechanical.
An implementation is built from the JSON alone, and nothing here is needed to decide a
verdict. What lives here is what the JSON deliberately refuses to hold: why the rules are
shaped as they are, the contracts that bind a reader of the record rather than the tree, and
the handful of warnings a cold writer earns the hard way. Where this file and `format.json`
appear to disagree, `format.json` wins and this file has a bug. This file's name tracks the
format's major version: `v0.md` is prose about the 0.x line.

## How a record ships its spec

A record ships its spec: `spec/format.json`, this directory, is part of the repository,
and "this file" in the spec's own text means the copy the record carries. A
checker is an interpreter of that copy, never an authority over it — two checkers reading the
same tree agree or one of them is wrong, and no checker's opinion adds or removes a rule.

Failure splits on readability. A spec the checker cannot read — JSON that will not parse,
or a value that cannot be taken as the shape the checker's reads demand, a limit that is
not a number, a field declaration that is null — is a tool error: the checker stops and
names what failed, because a verdict computed with a rule silently off is the defect this
format exists to detect — and it stops rather than reading the tree by the shipped copy,
because a verdict from an authority the tree never carried is the same wrong, quietly. A
spec that reads but is incoherent — an unknown key, a partial
map, a mirror that disagrees — is a conforming checker's ordinary output: the
self-consistency rules (M-27, M-28 and their kin) exist so that incoherence is reported as
violations against the spec file, not improvised around. Unreadable is silence with an
error code; reads-but-incoherent is red.

Rules are read over a commit's tree; the base note pins it. The why is atomicity:
what lands in one commit is judged as one tree — an Evidence and the artifact that
references it may arrive together and neither is ever red alone. A run against a working
directory is a preview, the verdict of the commit about to be made; the record's own answer
stands at commits, and no half-written tree holds it red.

Derived views — boards, lineage walks, needs-a-look flags — are defined over conforming
records. A view may read a red tree, but nothing it shows there is promised; the rules are
the floor a view stands on.

## The version

`version` is semver read over records, not over code, and it is pre-1.0.0: a minor bump may
fail an existing conforming record, a patch may not, and the format is not yet stable. The
number moves independently of any package's version, and equality between the two at any
moment is coincidence promising nothing. No record-failing bump ships without stating the
remedy — a publishing precondition no rule checks, and the format's first unenforceable
promise, named as one. The second is write-once: an artifact whose type declares
`mutable` false is authored once and thereafter untouched — a promise about history, and
history is a thing no rule reads; tooling that does read it may enforce what the rules
do not. The third is Evidence's Source field: its declaration says the value is never a
markdown link, and no rule reads that sentence — it binds the writer, not the checker.
Naming the promises is the design: the format states exactly which of its claims the tree
cannot show, so a reader never mistakes an unenforced promise for an enforced one.

## Where the 0.x line stands

The 0.x line is a working stage, not an offer. The rules exist, and the conformance suite
exists — it is what constructs the parsing section's fixtures — but the suite is not yet
published. The rules are the floor and a view is the payoff, so a record authored under 0.x
pays the full authoring cost for as long as the floor is the whole product — a cost this
project accepts for itself and asks of no one. The test of stability is concrete: a second
implementation agreeing with the first across the published suite. Until then, part of the
format's precision lives in the rules' own prose, and prose is not a fixture. The record
carries the Decisions that were argued; a rule that arrived without an argument — about
half of them, at 0.1.0 — is not yet ruled anywhere, and the gap is known rather than
closed by a sentence here.

## Reading format.json

Orientation for the first read, since the declarations are normalized rather than narrative:

- **Where a field lives is assembled, not stated per field.** A type's `fields` object
  declares every field, but which run each belongs to is decided by the event maps and
  M-19, not by anything visible in the declaration itself — declaration order implies
  nothing, and a field that sits beside `Opened` in the JSON may still be event-carried.
  Read M-19 before trusting an intuition about placement.
- **Field names are reserved words of the record, not of the type.** That is the tripwire's
  framing: a field-shaped line with any type's declared label, outside a run, is how a field
  would drift silently out of the machinery — or ape another type's and look live while
  doing nothing — which is why a stray declared label is never demoted to prose. Fences
  quote anything.
- **The em dash is load-bearing.** The event grammar requires the spaced em dash (U+2014)
  literally, and a heading that carries a title joins it with the same character; a hyphen
  there is not a stylistic variant but a different line — a heading that fails its grammar,
  or an event near-miss the event grammar owns. Copy the character; do not type an approximation.
- **`mirrors` is a small function notation, not prose.** M-27 defines it. The notation
  exists so a copied value can name its sources precisely enough to be recomposed and
  compared — the literal is never trusted, only checked.
- **The parsing section carries its own teeth.** Its four fixture shapes are constructed in
  the conformance suite; the section is spec, not commentary, and drift between its prose
  and an implementation is caught by fixtures, not by rereading.

Two of these are ergonomic tripwires and will be most writers' first reds. A declared label
is ordinary English — Status, Kind, Source — so a field-shaped line carrying one in prose
trips the machinery until a fence quotes it; and editors substitute hyphens for the em dash
unasked. Both reds are the doctrine working, named here so the first encounter reads as the
format's strictness rather than the writer's failure.

## Doctrine

**One mistake, one red — and the co-fix question.** Where one authoring mistake would
surface as several violations, the rules merge or pass over so the report points at the
mistake, not at its debris. The question asked when each merge was ruled: does fixing one
red necessarily fix the other? Where yes, the reds were judged one mistake; where each can
be fixed while the other stands, they are two facts and both fire. This is the design
heuristic behind the merges the rules perform — it predicts nothing on its own: every merge
and pass-over lives in some rule's text, and a pair of reds no rule merges stays two reds
whatever the heuristic would say. The misplaced-run merge is the heuristic's sharpest
outcome, and its partial form is the heuristic honestly applied: stranding a block's fields
outside its run is one layout mistake, but an absence is not a layout mistake — and the
all-merging alternative was rejected because it punished the half-misplaced block harder
than the fully misplaced one.

**Standing claims and testimony.** A field value some rule reads against the present tree —
a blocker, a post-gate Scope, the declared Status — is a standing claim and must stay true;
when the tree moves out from under it, the red is a pager and the remedy is a one-line edit
or the reopening ceremony. A value read as history — a Forced by — is testimony, and
testimony cannot go stale, which is why it rides events: each event's value is that event's
statement, made once and never owed maintenance.

**External content is re-derived, not linked.** The web is cited by restating it as this
record's own Evidence — copy or paraphrase into something the tree can watch — with the URL
carried as data in Source, backtick-wrapped so no fragment of it feeds the reference scan.
An external Source is legal in both forms: the whole value as the wrapped URL, or prose
carrying a wrapped URL. The wrap is what protects the URL; the surrounding words earn no
protection from it — they are prose, and a bare ID among them is a reference like anywhere
else. A cross-record ID is
written as a code span, a trace the scans ignore, and it lives in body prose only: field
values name this record's artifacts or nothing.

**No invisible ink.** A comment renders as nothing while its interior parses at full
strength, so the operative record and the rendered record could diverge — at the Ruling,
catastrophically. The comment is banned rather than masked because masking would make the
divergence legal; code is the opposite trade, visible and inert, and is the escape for
quoting one. Other raw HTML renders at a renderer's discretion and stays prose — the comment
is the one construct every renderer hides, and the one banned.

**A rejected stem is inert.** A file under a home whose stem the grammar rejects does not
belong, and that is its whole story — the one red is the eviction notice, and every further
red on a file that must leave anyway would be noise. It keeps just enough standing (a stem
in the namespace, a file that links can reach) that its neighbours' verdicts stay stable
while it waits to be renamed or moved; M-02 states the mechanics.

**Pinning decisions are earned by divergence, not completeness.** A reading gets pinned in
`format.json` when two conforming implementations could otherwise disagree on a green file, or
call the same file green and red. A reading that only redistributes reds among rules, or
governs files already red, may stay in prose — here — until practice shows otherwise.

**A Decision exists from the moment the question is asked.** An argument in progress needs a
legal home, or it takes one anyway — Work items swell into decisions in disguise while the
checker reports clean. An open Decision is that home: closing appends an event rather than
creating the file, Work stays small enough for its word budget to mean something, and the
record can say what is settled versus what is deliberately open. The cost is many open
Decisions at once, and the defence is the written settling condition.

**One observation under one Grade.** An Evidence entry is one observation when its Grade is
true of everything in it — provenance, not claim count. Several claims read from one source
under one grade are one honest entry; the moment a grade is true of only part, the entry is
two. The test is stateable but not decidable from the tree, so it binds the writer and the
reviewer, and nothing mechanical will catch the next bundle.

**A closing says what happened.** A Work closing carries an Outcome for the same reason a
Decision's carries a Ruling: the event says what it did, not only that it happened — without
it, Done when is decorative at the only moment it matters. Abandonment earned no event of
its own: an abandoned item closes with an Outcome that says so, because nothing downstream
would treat the two differently — a substitute, not a distaste.

**Reopening is history, not forecast.** Whether a Ruling holds only for now is not a property
the format knows: any marker rule would check the vocabulary, not the behaviour. A ruling
that stops holding is reopened, with a date, after the fact; Reopens when stays an optional
field on a closing, worth writing and worth reading — a view's watch item, never a rule's
subject.

**An ID is a label, not a key.** An ID is read at every citation and written once, so the
grammar spends its budget on the reader: a name, not a number. The one real cost is
staleness, and its answer lives beside the grammar rather than here: a rename would break
every citation and the commit messages carrying them, which cannot be edited, so the title
absorbs corrections and the ID absorbs none.

**A record is a git repository; a forge is a tier above.** Git alone buys what the tree
cannot reach — the merge-lost closing, Evidence immutability as checkable history — and
needs no network. A forge buys review state and the pull request as a unit, and stays a tier
because a record that requires a forge requires a vendor. The repository itself is what git
reports present and not ignored; no git is an error, not a fallback.

## The dialects and where they come from

**Globs are gitignore's, stated, except where they deliberately are not.** The `**` reading
is gitignore's because the record is git-fueled and its authors already hold that model. The
`!<` marker is the deliberate exception: it marks an absent-glob — the path has been eaten
and must stay gone, the record's deletion idiom — and it is this dialect's own coinage
precisely because gitignore's `!` means something else; a marker with no prior anywhere
cannot be misread, only unknown, and unknown sends the reader to the dialect row.

**Links are CommonMark's, in a line-oriented subset.** Fences and inline spans are the whole
code subset — indented code blocks are not code here, and a span never crosses a line,
because the record is diff-oriented and a construct whose meaning spans lines makes a
one-line diff deceptive. Reference links are CommonMark's three forms, because a rendered
link no rule can see is invisible ink's little cousin; a bracketed token with no matching
definition is not a link — its interior is ordinary text to the scans, like any prose. An
image is a link to the rules that read destinations — the existence checks bind it, the
text rules pass it over, and no rule binds its alt text. A destination resolves as a
renderer resolves a click, and every rule reads the one resolved root-relative path — one
shared resolution, so no two rules can disagree about where a link points. A leading `/`
resolves from the repository root — the forge's reading, and the path vocabulary the rules
already speak; the cost, accepted consciously, is that IDE raw-file previews show these
links broken, and the readers of record live at the forge.

**Partitions keep the link rules from disagreeing.** Paths partition by root-relative
destination: under `record/` a link is M-01's alone, everywhere else M-13's. Among internal
destinations, the text rules partition by what the home-walk gathers: an artifact
destination is M-24's alone, everything else M-18's — and an external destination belongs
to M-13 entirely, its link text unbound, so the wrong-form red is never joined by a
text-agreement red. In every case the boundary is computed the same way by the rules on
both sides of it, so no link is ever two rules' business.

**The bare-web scan reads prose, not plumbing.** Destinations and titles are a link's
plumbing and the scan excludes them; link text is prose and the scan reads it — a boundary
forced by a real case, the URL smuggled into a link's text, which was wrong-but-green under
the blanket exclusion this boundary replaced. A definition line stays unread, a ceiling
priced against the unused-definition ceiling it already lives with.

## The context file

`record/context.md` is charter, not record: it states what the project is, uncontested, and
anything that wants a *because* belongs in a Decision. The derivability rule draws its
boundary: what the record can derive, the record states — the file carries only what cannot
be derived. Absence is a state, not an omission: a project with nothing underivable to say
omits the file, and omission is the one legal form of that silence — a committed sentinel,
or the empty file that is the sentinel with fewer characters, is a form mistaken for a
statement.

## Views, not rules

The format routes *needs-a-look* to views and reserves rules for *wrong*. A Scope whose gate
never opened — its implementing Work never named the Decision — is a view's flag, because no
rule can demand the naming. Supersession forks are a view's question — two rigs may honestly
both replace the same measurement, and only a cycle is wrong. Staleness of an
implementation closed before a reopening, a Decision carrying Reopens when, a Blocked-by
deadlock — each is an honest record of a real situation a human must break, needs-a-look,
never wrong-at-write. Ordering among Recorded dates needs not even that: it is import
order, which is what the field records.
The deadlock is the teaching case: a Supersedes cycle leaves no measurement current and is
wrong the moment written, while a blocker cycle among distinct Work items states a true and
unfortunate fact; the rules ban the first and deliberately keep the second legal. The one
exception proves the boundary: a Work blocked by itself is no deadlock but a loop no human
can break and no closing can clear, and self-reference in a field is wrong-at-write for
every field — a field edge that loops is no lineage, and no statement.

## Why probe is a Kind

`probe` exists because the method wants measurement as first-class work: a question you pay
for with a harness run deserves the same opening, closing and budget discipline as a build,
and its Probes field is the lineage's front door — what it addressed at open, what it
settled or produced at close. `build` is everything else. Two kinds, because the method
distinguishes exactly two ways work relates to evidence: producing it, and acting on it.

## What Recorded dates

`Recorded` dates the recording, not the measurement: the recording is the record's own act,
made at writing and corroborable by the history that carries it, while the measurement's own
date is a claim nothing in the tree can check — prose, when it matters, never this field.
